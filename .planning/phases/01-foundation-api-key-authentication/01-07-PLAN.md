<objective>
Close verification gaps 1 and 3 and the linked review findings CR-01, CR-03,
WR-02, WR-03, WR-04, and WR-06: interactive `auth login` echoes the API key,
ignores TLS settings, silently drops auth-group output flags, can accept keys
the redactor will not mask, and persists a profile from a 2xx `/usage` body that
does not contain scopes.

Purpose: authentication is the phase's first user action. If login is echoed,
cannot reach a private-CA server, or writes an untruthful profile, the rest of
the CLI is built on a credential the user cannot trust.

Output: a hidden-input-only prompt, a login profile built by `Config::Resolver`,
TLS/output options on the auth group, consistent secret-length enforcement, and
strict `/usage` response validation.
</objective>
